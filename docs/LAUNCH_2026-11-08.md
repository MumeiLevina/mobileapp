## Operator commands (never paste output containing secrets into issues)
On a clean dedicated checkout at the chosen **reviewed integration commit** (do not reset dirty native worktrees):
```bash
npm ci
npm run typecheck
npm run lint
npm test
npm run eval:safety
npm run test:mobile
npm run test:database
npm run build:api
npm run test:e2e
```

Use isolated *staging* environment variables, after confirming project identity and migrating only reviewed schema:
```bash
npm run preflight:staging
npm run test:supabase
npm run verify:staging
npm run eval:safety:staging
```
`verify:staging` can create/delete synthetic accounts and must **never** point at production.

The `apps/mobile/eas.json` `preview` profile is an internal **Connected** APK, `production` is a store artifact profile, and `demo-qa` is disconnected/synthetic. Review the exact build method, signing and environment before initiating any local or EAS-cloud build. A JS/native export is not an APK. Preserve local worktrees and never push APKs or secret env files to Git. After building, verify through Android tooling (`aapt dump badging`, `apksigner verify --print-certs`) and compute `sha256sum` on the **actual** signed APK. Record target SDK from the built manifest; Expo SDK 57 defaults to Android target API 36 per Expo documentation but the artifact is authoritative.

- Google Play new apps/updates submitted from 2026-08-31 must target Android API 36+ (verify the AAB).
- For **personal** Play Console accounts created after 2023-11-13, production access normally requires **12 closed testers opted-in continuously for >=14 days**, followed by an application/review. If not already completed, 8 Nov Play Production is not a reliable promise.
- Play Console requires privacy/data safety and app account deletion web resources; Mori's in-app deletion alone does not satisfy the external-resource requirement.
- Complete the Health apps declaration appropriate to Mori's wellbeing/mental-health-related functionality; do not imply clinical certification.
